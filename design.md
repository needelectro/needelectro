# NEED ELECTRO Design System

## 1. Design Direction

NEED ELECTRO should feel:

-   Professional
-   Modern
-   Trustworthy
-   Technology-driven
-   Clean
-   Fast
-   Practical
-   Premium without being excessive

The current brand identity uses blue, black, white, and light
backgrounds. Preserve this recognizable identity while creating a modern
digital interface.

## 2. Brand

### Name

NEED ELECTRO

### Tagline

Trusted Electrical and Technological Solutions

### Visual Identity

The lightning symbol and NEED ELECTRO wordmark should remain
recognizable.

Do not distort or unnecessarily redesign the logo.

## 3. Color Direction

Use the existing brand blue as the primary accent.

Suggested palette:

Primary Blue: `#087FE5`

Dark: `#111827`

Black: `#000000`

White: `#FFFFFF`

Light Background: `#F5F8FC`

Border: `#D9E2EC`

Success: `#16A34A`

Warning: `#F59E0B`

Error: `#DC2626`

The final implementation may refine these values after matching the
official logo assets.

## 4. Typography

Use a modern, highly readable sans-serif.

Recommended:

Inter

Alternative:

Plus Jakarta Sans

Bangla-ready fallback fonts should be supported when Bangla is
introduced.

## 5. Layout

Use a clean responsive grid.

Desktop:

-   Maximum content width around 1200--1400px.
-   Generous whitespace.
-   Clear section hierarchy.

Mobile:

-   Full-width content.
-   Compact navigation.
-   Large touch targets.
-   Simple forms.
-   Sticky important actions where appropriate.

## 6. Buttons

Primary button:

Blue background with strong contrast.

Secondary:

White or neutral background with border.

Danger:

Use only for destructive actions.

Buttons should clearly communicate:

Book Service

Shop Now

Buy Now

Accept Job

Track Order

Check Warranty

Become a Technician

## 7. Cards

Products

Technicians

Orders

Support tickets

Avoid excessive shadows.

Use subtle borders and moderate radius.

## 11. Service UI

Service cards should show:

Icon/image

Service name

Short description

Price or pricing model

Rating where applicable

Book button

## 12. Product UI

Product cards should show:

Product image

Brand

Product name

Price

Discount where applicable

Availability

Warranty indicator

Add to Cart

## 13. Technician UI

Technician cards should show appropriate public information:

Profile photo

Name

Verified badge

Skills

Rating

Completed jobs

Service area

View Profile

Do not expose sensitive information.

## 14. Status Design

Use clear status badges.

Examples:

Available

Pending

Verified

Assigned

On The Way

Working

Completed

Cancelled

Refunded

Suspended

Use color consistently, but never rely on color alone.

## 15. Forms

Forms should be:

Short

Clearly labeled

Keyboard friendly

Mobile friendly

Validated

Provide inline error messages.

Show progress for multi-step flows such as booking and technician
registration.

## 16. Booking UX

Use a multi-step booking interface:

Service

Problem

Location

Date and Time

Review

Confirmation

Show a summary before final submission.

## 17. Checkout UX

Use:

Cart

Address

Delivery

Payment

Review

Confirmation

Do not hide important fees.

## 18. PWA UX

The PWA should feel app-like.

Use:

Bottom navigation

Fast transitions

Install prompt

Splash/loading state

Offline fallback

Push notification support

Avoid browser-like layouts when installed.

## 19. Accessibility

Support:

Keyboard navigation

Visible focus

Semantic HTML

Accessible forms

Readable font sizes

Sufficient contrast

Screen reader labels

Touch targets appropriate for mobile

## 20. Animation

Use subtle animation only.

Good examples:

Button feedback

Card hover

Page transitions

Loading skeletons

Status transitions

Avoid distracting animations.

## 21. Empty States

Every empty page should explain what happened and what the user can do
next.

Example:

No bookings yet.

`Book your first service`

## 22. Error States

Errors should be understandable.

Do not display raw stack traces or database errors.

Provide:

What happened

What the user can do

Retry

Support option where appropriate

## 23. Brand Tone

Use language that is:

Clear

Professional

Friendly

Confident

Practical

Avoid exaggerated claims such as "guaranteed best" unless legally and
operationally substantiated.

## 24. Mobile Priority

On mobile, prioritize:

Book Service

Emergency Service

Shop

Track Booking

Track Order

Warranty

Support

## 25. Design Principle

Every screen should answer:

What can the user do here?

Make the primary action obvious.

Do not overload the interface with unnecessary information.
